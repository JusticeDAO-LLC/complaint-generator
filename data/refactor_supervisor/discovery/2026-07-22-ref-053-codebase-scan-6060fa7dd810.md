## Resolution

The flagged branch enriches completed session results with optional run and HACC
search metadata. Keeping that enrichment best-effort is appropriate because seed
complaints can come from external evidence packages and malformed optional
metadata should not discard a valid session result. The blanket handler,
however, silently treated every programming or runtime error as successful
enrichment.

The recovery path now encloses only external metadata normalization and catches
the data-shape and conversion errors expected there (`TypeError` and
`ValueError`). It logs the session identifier and traceback and leaves the
original seed complaint unchanged. Result mutation happens outside that narrow
boundary, and unexpected failures propagate so defects are visible rather than
being misreported as successful metadata attachment.

## Focused Validation

`tests/test_ref_053_harness_result_metadata.py` verifies both sides of the
boundary: malformed optional seed metadata is logged without losing the session
result, while an unexpected runtime failure is not swallowed.
