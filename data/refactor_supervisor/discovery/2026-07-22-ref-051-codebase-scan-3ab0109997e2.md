## Resolution

The flagged branch supports best-effort JSON serialization of timestamp-like
objects used in persisted session progress and progress callbacks. Falling back
to an object's attributes or string representation is appropriate when its
`isoformat()` method rejects the conversion, but silently catching every
exception hid both malformed metadata and unexpected runtime defects.

The conversion now catches only the expected conversion failures (`TypeError`,
`ValueError`, and `OverflowError`), logs the object type and traceback before
using the existing fallback representation, and allows unexpected failures to
propagate. This keeps progress metadata resilient without presenting arbitrary
implementation failures as successful serialization.

## Focused Validation

`tests/test_ref_051_harness_json_sanitizer.py` verifies that an expected
`isoformat()` conversion failure is observable and still produces a safe
fallback, while an unexpected runtime failure is no longer swallowed.
