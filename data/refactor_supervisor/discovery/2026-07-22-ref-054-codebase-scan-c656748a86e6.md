## Review Outcome

The finding identified a real runtime bug in
`AdversarialHarness._create_mediator_for_session`. Its broad exception handler
covered both signature inspection and mediator construction. If a factory that
accepted session-specific arguments failed while constructing a mediator, the
harness silently called that factory a second time without arguments. This could
duplicate constructor side effects, discard session-specific storage paths, or
replace the original failure with a misleading second error.

The recovery boundary now covers only `TypeError` and `ValueError` from
`inspect.signature`, which are the documented failures for unsupported
callables. That compatibility fallback is logged and invokes the no-argument
factory once. Factory execution occurs outside the handler so all constructor
failures propagate without retry. Keyword filtering also excludes
positional-only parameters, preventing them from being passed illegally by
name.

Focused regression tests verify supported keyword forwarding, logged fallback
for an uninspectable callable, propagation without retry for factory failures,
propagation of unexpected inspection failures, and positional-only filtering.
